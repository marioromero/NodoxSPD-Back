Registro

Cuando alguien entra a la web de la Pyme, el script del widget se carga en silencio — sin interrumpir la página ni ralentizarla. Antes de mostrar el banner, el sistema ya fijó los valores por defecto: todas las cookies opcionales bloqueadas.

tiendaejemplo.cl
Este sitio usa cookies
Usamos cookies para mejorar tu experiencia. Puedes elegir cuáles aceptar. Las cookies técnicas siempre están activas porque el sitio no funciona sin ellas.
Antes del banner

Google Analytics, Meta Pixel, Hotjar y todos los scripts de rastreo están bloqueados. No se ha cargado ninguno.

Lo que ve el usuario

La página carga normalmente. El banner aparece en la parte inferior sin bloquear el contenido del sitio.

El banner muestra cuatro categorías de cookies, cada una con un propósito diferente. Solo las técnicas son obligatorias — el usuario decide libremente sobre las demás.

Importante: Los switches de arriba son interactivos. Prueba activarlos para ver cómo cambia el estado — así funciona el banner real que verán los usuarios de la Pyme.

El usuario hace clic en "Guardar preferencias". En ese instante ocurren dos cosas en paralelo: una inmediata (para Google) y una silenciosa en segundo plano (para nuestro registro legal).

Lo que ocurre al hacer clic
Acción 1 — Inmediata (milisegundos)

Las preferencias se guardan en el dispositivo del usuario (localStorage). Google recibe el estado de consentimiento al instante mediante Consent Mode v2. El sitio reacciona de inmediato: si aceptó analítica, GA4 se activa ahora.

Acción 2 — Segundo plano (invisible)

El widget envía las preferencias a nuestra API. El usuario no espera esto — ya puede seguir navegando. Si la API tardara o fallara, las preferencias locales ya están guardadas y el sitio no se rompe.

Mapeo de propósitos a tecnologías
Google (GA4 + Ads)

Recibe analytics_storage, ad_storage, ad_user_data. Respeta el estado sin que el widget toque ningún script directamente.

Meta Pixel, TikTok...

El widget carga sus scripts dinámicamente solo si el usuario consintió. Si rechazó, esos scripts nunca se ejecutan en el navegador.

Dependiendo de lo que el usuario eligió, el widget activa o mantiene bloqueados los scripts de terceros. Este es el mecanismo técnico real de control.

Ejemplo: usuario aceptó analítica, rechazó publicidad
Google Analytics activado gtag('consent','update', {analytics_storage:'granted'}) → GA4 empieza a registrar visitas
Hotjar activado El script de Hotjar se inyecta dinámicamente en la página → empieza a grabar mapas de calor
Meta Pixel — bloqueado El script nunca se cargó. No existe ninguna cookie _fbp en el navegador del usuario.
Google Ads — bloqueado ad_storage:'denied' · ad_user_data:'denied' → Google no crea cookie de remarketing
Cookies técnicas — siempre activas sesión, carrito, seguridad: nunca bloqueadas, nunca preguntadas.

Responsabilidad de la Pyme: Para que el widget pueda bloquear Meta Pixel o Hotjar, la Pyme debe quitarlos de su HTML y declarar los IDs en el panel de configuración. Si los tiene pegados directamente en el código, corren antes del banner y el widget no puede hacer nada.

En paralelo a todo lo anterior, nuestra API recibe las preferencias y genera un sello criptográfico único — la prueba legal de que ese usuario, en ese momento, consintió exactamente esos propósitos con esa versión de política.

Qué contiene cada registro en el ledger
visitor_uuid: "f47ac10b-58cc-4372-a567-..."
company_id: 142
policy_hash: "sha256:3a9f2c8d..." ← versión exacta de la política
purposes: {necessary:true, analytics:true, marketing:false}
consent_occurred_at: "2026-06-23T14:32:11Z"
capture_method: "live_widget"
proof_hash: "sha256:8b4e1a7f..." ← sello que vincula todo
Qué garantiza cada campo
visitor_uuid — identifica el navegador donde ocurrió el consentimientoNo es la persona, pero es el contexto técnico verificable donde se tomó la decisión
policy_hash — versión exacta de la política que leyó el usuarioSi la política cambia después, este hash prueba que el usuario vio la versión vigente en ese momento
purposes — qué aceptó y qué rechazó, con precisiónNo "aceptó todo" — el log guarda cada categoría por separado: analítica sí, publicidad no
consent_occurred_at — momento exacto de la decisiónEste timestamp es previo a cualquier procesamiento de datos — cumple el requisito de consentimiento previo
proof_hash — sello que vincula todo de forma inalterableSi alguien intenta modificar el registro posterior, el hash no coincide — el fraude es detectable
El ledger es append-only

Ningún registro puede borrarse ni modificarse. Solo se pueden agregar nuevos. Ante una fiscalización de la Ley 21.719, la Pyme puede mostrar exactamente qué consintió cada usuario y cuándo.
