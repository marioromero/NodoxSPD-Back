Estándares de API

Convenciones generales del proyecto: formato de respuestas, manejo de errores, autenticación y control de acceso. Aplica a toda la aplicación, independientemente del módulo.

Visión General

Formato de Respuesta JSON

Todos los endpoints del sistema responden con una estructura JSON consistente. No importa si es éxito o error — el contrato es siempre el mismo:

{
  "status": true | false,
  "message": "Mensaje legible para el frontend",
  "data": { ...payload o null }
}

Reglas:

  • status → true en 2xx, false en 4xx/5xx
  • message → frase corta en español, legible para el frontend
  • data → el payload de la respuesta, o null en errores sin contenido adicional
  • En errores de validación (422), data.errors contiene un objeto con los errores por campo

ForceJsonResponse

app/Http/Middleware/ForceJsonResponse.php

Es el primer middleware en ejecutarse (registrado con prepend en el stack global). Fuerza que toda respuesta sea application/json, ignorando el header Accept del cliente. Por ser una API pura — nunca se devuelve HTML ni XML.

Violaciones de Reglas de Negocio

bootstrap/app.php — handler de LogicException

Las LogicException capturan violaciones de reglas de negocio que no pueden expresarse como validación simple. El caso principal es la inmutabilidad del ledger: cuando se intenta hacer update() o delete() sobre un ConsentLog, el modelo lanza LogicException y el handler responde con 409.

Esto asegura que ningún código (intencional o accidental) pueda modificar registros de consentimiento, protegiendo la integridad forense del sistema.

Autenticación y Control de Acceso

Sanctum — API Tokens

Laravel Sanctum · config/sanctum.php

La autenticación se maneja con Laravel Sanctum. Al registrarse o iniciar sesión, el backend emite un token que el frontend (Angular) debe enviar en cada request autenticado mediante el header Authorization: Bearer {token}.

Endpoints públicos vs protegidos:

  • Públicos: /api/register, /api/login, /api/plans, /api/public/policies/{hash}
  • Protegidos (auth:sanctum): /api/me, /api/logout, todo bajo /api/company y /api/portal

Las sesiones web (Stateful API) están habilitadas vía $middleware->statefulApi() en bootstrap/app.php, lo que permite también autenticación desde el panel admin con cookies de sesión.

Spatie — RBAC (Roles y Permisos)

vendor/spatie/laravel-permission

El paquete Spatie Laravel Permission implementa control de acceso basado en roles. Se usa para distinguir entre los tipos de usuario y aplicar permisos granulares.

Middleware registrados como alias:

  • role → RoleMiddleware — verifica que el usuario tenga un rol específico
  • permission → PermissionMiddleware — verifica permisos específicos

Roles actuales:

  • company_admin — administrador de una Pyme cliente. Accede a /api/company/*
  • person — persona natural. Accede a /api/portal/* (aún en desarrollo)

La estructura de tablas (roles, permissions, model_has_roles, etc.) está lista para granularidad fina en el futuro.

CheckCompanyOnboarding

app/Http/Middleware/CheckCompanyOnboarding.php

Middleware registrado como alias onboarding.check que verifica que la empresa haya completado su configuración inicial antes de acceder a los módulos core del SaaS.

Qué protege: La "Zona Estricta" donde están los módulos de la Ley 21.719 (Trust Widget, Políticas, ARCO+P, Brechas).

Qué no bloquea: La facturación y endpoints de onboarding, para no impedir pagos ni la configuración inicial.

Se aplica como middleware de grupo en rutas específicas dentro de /api/company/*.
