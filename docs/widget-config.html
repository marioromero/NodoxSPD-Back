API Pública del Trust Widget

Controlador, seguridad, rate limiting y estrategia de caché para CDN del endpoint de configuración del widget embebible.

WidgetConfigController

WidgetConfigController

app/Http/Controllers/Api/Widget/WidgetConfigController.php

Controlador público del Trust Widget. Único endpoint: show(). Resuelve la configuración del widget embebible para una empresa, sin requerir autenticación.

Flujo del método show()

1Valida que $publicUuid sea un UUID v4 válido (regex RFC 4122). Si no: 400.
↓
2Resuelve la empresa con Company::where('public_uuid', $uuid)->firstOrFail(). Nunca por ID numérico. Si no existe: 404.
↓
3Obtiene la política de cookies activa: document_type = 'cookie_policy', status = 'published', excluye workers_policy (defensa en profundidad).
↓
4Si no hay política: 404 con no_active_policy. Si existe: extrae widget_config de la empresa y construye los propósitos.
↓
5Ensambla respuesta JSON (sin IDs internos) y aplica headers de caché para CDN.

Seguridad

Validaciones y Filtros

El endpoint aplica tres capas de seguridad en el controlador:

  • Validación de UUID: El parámetro $publicUuid se valida con una expresión regular que verifica el formato UUID v4 (RFC 4122). Cualquier string que no cumpla recibe 400.
  • Resolución por public_uuid: La empresa se busca exclusivamente por su identificador público. El ID numérico interno (id, company_id) nunca se expone en la URL ni en la respuesta.
  • Filtro de política activa: Solo se devuelve configuración si existe una política de cookies con status = 'published'. Además se fuerza document_type = 'cookie_policy' y se excluye explícitamente workers_policy como defensa en profundidad.
Regla estricta: La respuesta JSON no contiene id, company_id, user_id ni ningún identificador interno. Solo datos públicos.

Rate Limiting Multicapa

config/rate_limits.php · app/Providers/AppServiceProvider.php

El rate limiter widget aplica tres límites simultáneos por cada request al endpoint. Si cualquiera de los tres se excede, Laravel retorna HTTP 429. Esto protege contra abusos sin depender de autenticación.

LímiteClaveValor por defectoVariable .env
Por visitantevisitor:{visitor_uuid}10 req/minRATE_LIMIT_WIDGET_VISITOR
Por empresacompany:{company_public_uuid}60 req/minRATE_LIMIT_WIDGET_COMPANY
Por IPip:{ip}5 req/minRATE_LIMIT_WIDGET_IP
Nota: El rate limiter por visitante depende de que el widget JS envíe el parámetro visitor_uuid en el query string. Si no se envía, ese límite no se evalúa, pero los otros dos (empresa e IP) siguen activos.

Estrategia de Caché Edge (Cloudflare)

WidgetConfigController.php — response headers

La respuesta está optimizada para caché en CDN (Cloudflare). Se envían los siguientes headers para que Cloudflare cachee la respuesta a nivel de edge y reduzca la carga en el servidor:

HeaderValorPropósito
Cache-Controlpublic, max-age=3600, s-maxage=3600, stale-while-revalidate=86400Permite caché pública (CDN y navegador) por 1 hora. Si el CDN tiene una copia stale, puede servirla por hasta 24h mientras revalida en segundo plano.
ETag"{public_uuid}-{policy_hash}"Identificador único de versión. Combina el UUID de la empresa con el hash de la política. Si cambia la política, el ETag cambia y el CDN invalida automáticamente.
VaryAccept-EncodingIndica al CDN que la respuesta varía según codificación (gzip, br). No incluye Origin porque CORS se maneja aparte con DynamicCorsMiddleware.
Sin Set-Cookie: La respuesta usa explícitamente ->withoutCookie('session')->withoutCookie('XSRF-TOKEN') para garantizar que Cloudflare no invalide el caché por presencia de cookies. Esto es crítico: si Laravel envía Set-Cookie, Cloudflare trata la respuesta como dinámica y no la cachea.
